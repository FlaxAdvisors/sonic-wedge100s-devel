  **Bug 1** (`poll_lpmode_hidraw()` ~line 799): Removed the `refresh_eeprom_lower_page()` call
  immediately after LP_MODE deassert. The QSFP module MCU resets on LP_MODE exit — attempting
  a 128-byte EEPROM read at that moment hung the I2C bus, permanently stuck the CP2112, and
  caused `show interface status` Type = N/A. The LP_MODE EEPROM cache written by
  `poll_presence_hidraw()` (while the module was in LP_MODE and responding) is sufficient.

  **Bug 2** (`service_write_requests()` ~line 1333): Added `cp2112_cancel()` at the top of this
  inotify-triggered function. The wedge100s-bmc-daemon writes fan/PSU files to /run/wedge100s/
  every ~5 seconds, triggering inotify → `service_write_requests()` → `apply_led_writes()` →

  them, the next inotify's `poll_lpmode_hidraw()` → `mux_select()` → `cp2112_wait_complete()`
  received stale CPLD responses instead of the correct mux write response.
